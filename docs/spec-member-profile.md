# 仕様書: 個人・メンバー収支詳細ページ

- 作成日: 2026-08-19
- 対象: 個人成績ページの拡張、および「友達」個々の収支詳細ページの新設
- 前提: 本ドキュメントは既存実装(`/me`, `/ranking`)を踏まえた追加仕様。既存の全体仕様書は本リポジトリに含まれないため、実装コードから逆算した現状分析を1章に記載する。
- **注記(同日追記)**: 本仕様の実装後、グループ機能自体が廃止され「友達」ベースに一本化された([[docs/spec-friends.md]] v2を参照)。以下の「グループ内順位」「ランキング」等の記述は、実装上はそれぞれ「友達内順位」「`/friends`の一覧」に読み替え済み。関数シグネチャから`groupId`引数も削除されている。この文書は個人・メンバー収支ページ自体の設計意図(期間フィルタ・連勝連敗・カレンダー等)の記録として残す。カレンダー機能は[[docs/spec-friends.md]]の後に追加実装(`ProfitCalendar`、`/me`・`/members/[id]`に表示、月ごとにその日の収支を確認可能)。

## 1. 現状分析(実装済み機能の棚卸し)

| 機能 | 状態 | 実装箇所 |
|---|---|---|
| 自分の収支表(通算収支・勝率・平均収支・参加回数) | 実装済み | `src/app/(app)/me/page.tsx` |
| 自分の収支推移グラフ | 実装済み | `src/components/ProfitTrend.tsx` |
| 自分の最大勝ち・最大負け | 実装済み | `src/app/(app)/me/page.tsx` |
| 自分の対局ごとの結果一覧 | 実装済み(対局詳細へのリンクなし) | `src/app/(app)/me/page.tsx` |
| グループ全員の一覧(通算収支・勝率・平均収支・参加数、ソート可) | 実装済み | `src/app/(app)/ranking/page.tsx`, `RankingTable.tsx` |
| **メンバー個人(友達)の詳細ページ** | **未実装** | ランキング表の行から詳細へ遷移する導線がない |

結論: 「勝率」「平均収支」「生涯収支(=通算収支)」は自分についてはすでに表示されている。不足しているのは、**友達=グループメンバー個々の詳細な収支表**(自分の`/me`相当のページ)であり、これが本仕様の主目的。あわせて、実装済み箇所とのコード重複を解消し、いくつかの小規模な追加指標を導入する。

## 2. 目的

グループランキングの各メンバーから、そのメンバー個人の詳細収支ページに遷移できるようにする。表示内容は自分の個人成績ページと同等(推移グラフ・最大勝敗・対局ごとの結果)とし、加えてグループ内順位・連勝連敗を表示する。

## 3. スコープ

### 3.1 今回実装する

1. 統計ロジックの共通化(`src/lib/stats.ts`)
2. メンバー詳細ページ `/members/[userId]` の新設
3. ランキング表からメンバー詳細ページへのリンク
4. グループ内順位バッジ(自分ページ・メンバー詳細ページ共通)
5. 現在の連勝/連敗数(streak)の表示
6. 対局ごとの結果一覧から対局詳細ページ(`/sessions/[id]`)へのリンク
7. 期間フィルタ(全期間 / 今年 / 今月)。個人成績・メンバー詳細・グループランキングの3ページ共通

### 3.2 今回はスコープ外(将来検討)

- メンバー対メンバーのヘッドトゥヘッド収支(対戦相手別の勝敗)。集計ロジックが複雑になるため別途検討。
- 収支表のCSV/画像エクスポート。
- 期間フィルタの「任意の期間を指定」(現状は全期間/今年/今月の3択のみ)。

理由: ユーザー要望の中心は「個人・友達の収支表(勝率・平均収支・生涯収支)を見られること」であり、上記2点は既存のランキング・個人ページで実質カバー済み、または優先度が低いと判断。追加が必要になった場合は別仕様として切り出す。

## 4. データ層の変更

### 4.0 期間フィルタ

`Period = "all" | "year" | "month"` を定義し、`getGroupStats` / `getUserProfile` の第3引数として渡す(省略時は `"all"`)。

- `periodRange(period)` は対象期間の `[from, to)` をUTC瞬時で返す(`"all"`は`null`)。サーバーの実行環境タイムゾーン(Vercelは既定でUTC)に依存せず、常に日本時間(JST, UTC+9)基準で「今月」「今年」の境界を計算する。
- 各ページは `?period=year` / `?period=month` のクエリパラメータで期間を切り替える(`PeriodTabs`コンポーネント、通常のリンク遷移でサーバーコンポーネントとして再取得)。
- 期間フィルタを適用すると、通算収支・勝率・平均収支・最大勝敗・連勝連敗・グループ内順位のすべてが、その期間内の対局のみを対象に再計算される。生涯収支を見たい場合は「全期間」(デフォルト)を選択する。

### 4.1 `src/lib/stats.ts`

既存の `getGroupStats` / `getUserStats` に加えて、詳細ページ用の集計関数を追加する。

```ts
export type SessionResult = {
  sessionId: string;
  sessionDate: Date;
  location: string | null;
  profit: number;
};

export type UserProfile = UserStats & {
  bestSession: SessionResult | null;
  worstSession: SessionResult | null;
  currentStreak: number; // 正=連勝数、負=連敗数(絶対値)、0=対局なし or 直近が引き分け(0円)
  trendPoints: number[]; // 通算収支の累積推移(古い順)
  sessionResults: SessionResult[]; // 新しい順
};

export async function getUserProfile(userId: string, groupId: string): Promise<UserProfile>;
```

- `getUserProfile` は対象ユーザーが参加した確定済み(`status: "confirmed"`)対局を日付昇順で取得し、`profitOf`(`src/lib/ledger.ts`)で対局ごとの収支を算出する。
- `currentStreak` は `sessionResults` を新しい順に走査し、符号が変わるまでの連続勝敗数を数える(0円の対局はストリークを打ち切る)。
- `/me` ページは `getUserProfile(user.id, groupId)` を呼ぶように書き換え、ページ内での重複計算ロジックを削除する(DRY)。

### 4.2 グループ内順位

`getGroupStats` の戻り値(`Map<userId, UserStats>`)を通算収支降順に並べ替えたうえで、対象ユーザーの順位(1始まり)とグループ人数を返す小ヘルパーを追加する。

```ts
export function rankOf(statsMap: Map<string, UserStats>, userId: string): { rank: number; total: number };
```

## 5. 画面仕様

### 5.1 メンバー詳細ページ `/members/[userId]`

- **アクセス制御**: `requireUserWithGroup()` で自分のグループを取得。対象 `userId` が同じ `groupId` の `GroupMember` に存在しない場合は `notFound()`。
- **自分自身の場合**: `/me` へリダイレクト(表示内容の二重管理を避けるため、自分の詳細は常に `/me` に集約する)。
- **表示内容**(`/me` と共通レイアウト、共通表示部分は `ProfileStats` コンポーネントに切り出し):
  - ページタイトル: `{表示名} の収支`
  - サブタイトル: グループ名 + グループ内順位(例: 「グループ内 2位 / 6人」、選択中の期間内での順位)
  - 期間タブ(全期間 / 今年 / 今月)
  - 通算収支・勝率・平均収支・参加回数(4枚のstat-tile、いずれも選択中の期間内の値)
  - 現在の連勝/連敗(例: 「3連勝中」「2連敗中」、ストリークが0の場合は非表示)
  - 収支推移グラフ(`ProfitTrend`コンポーネントを再利用)
  - 最大勝ち・最大負け(日付付き)
  - 対局ごとの結果テーブル(新しい順、各行を `/sessions/[id]` へリンク)
- 表示専用ページであり、編集操作は行わない。

### 5.2 `/me` ページの変更

- ロジックを `getUserProfile` 呼び出しに置き換え、表示部分は `ProfileStats` を共用(`/members/[userId]` と重複コードを排除)。
- 追加: 期間タブ、グループ内順位バッジ、連勝/連敗表示、対局結果行から対局詳細へのリンク。

### 5.3 ランキング表 (`RankingTable.tsx` / `ranking/page.tsx`) の変更

- 期間タブを追加し、選択中の期間内の集計をランキングに反映。
- メンバー名セルを `Link` に変更:
  - 自分の行 → `/me`
  - 他メンバーの行 → `/members/[userId]`
- 見た目上のインタラクション(下線 or ホバー色)を追加し、リンクであることが分かるようにする。

## 6. 非機能要件

- 追加ページも既存同様、素のCSS(`globals.css`)のクラス(`page-shell`, `stat-grid`, `stat-tile`, `table-scroll` 等)を再利用し、独自のスタイルシステムを増やさない。
- グループの最大人数は10人程度のため、`getGroupStats` の全件取得アプローチ(N+1なしの一括クエリ)は維持で問題ない。パフォーマンス最適化は不要。
- 認可漏れ防止: `/members/[userId]` は必ずグループ一致チェックを行い、他グループユーザーのデータが閲覧できないことをテストする。

## 8. 受け入れ基準

- [ ] ランキング画面の各メンバー名をクリックすると、そのメンバーの収支詳細(推移グラフ・最大勝敗・対局一覧・勝率・平均収支・通算収支)が表示される。
- [ ] 自分の名前をクリックすると `/me` に遷移する。
- [ ] 他グループのユーザーIDを直接URLで指定してもアクセスできない(404)。
- [ ] `/me` と `/members/[id]` にグループ内順位と連勝/連敗が表示される。
- [ ] 対局ごとの結果テーブルの行から対局詳細ページに遷移できる。
- [ ] 対局参加0件のメンバーでもエラーにならず、空状態が適切に表示される。
- [ ] 個人成績・メンバー詳細・グループランキングの各ページで「全期間/今年/今月」を切り替えられ、切り替えた期間の対局のみを対象に全指標(収支・勝率・平均収支・最大勝敗・連勝連敗・順位)が再計算される。
- [ ] 「今月」「今年」の範囲は日本時間(JST)基準で判定される(デプロイ先サーバーのタイムゾーンに依存しない)。
